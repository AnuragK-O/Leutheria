# Leutheria interface: design reference

The main window and the activation overlay share one visual language. This file is the
reference for it: what each token is, its value in both themes, and the rules for using
them. It is written so that a change stays consistent with what's there, and so the Qt
overlay (`overlay-qt/`) can be ported from it without reading the CSS.

**Where things live**

| what | where |
|---|---|
| Every token (colour, type, space, geometry, motion) | the first two blocks of `styles.css`: `:root` (dark, the default) and `[data-theme="light"]` |
| Shared primitives (cut corner, buttons, tags, fields, panels) | `styles.css`, the `primitive:` sections |
| Overlay plate, reticle, compact confirmation card | `overlay/overlay.css` (uses the tokens and primitives above; defines none of its own) |
| Floating panels: frame, control strip, per-panel layouts | `panels/panels.css` (same rule: no tokens of its own) |
| User overrides: theme, density, accent | `js/appearance.js` applies them in every window, on top of the tokens |
| Fonts and their licences | `fonts/` |
| Logo mark, downsized and transparent | `img/mark-{64,128,256,512}.png`, regenerated by `app/scripts/make-mark.js` |
| Icons | `PATHS` in `js/util.js` |

No component rule mentions a theme. The light theme overrides tokens and nothing else;
keep it that way, or the two themes drift.

## The idea

Leutheria runs commands on your computer. The interface is its control surface: it shows
what the machine did, what it is doing, and what it is waiting for you to allow.

- **Colour means state, never decoration.** Violet is the brand and "this is selected or
  primary". Cyan is live. Amber is waiting on you. Red failed or destroys. Green
  succeeded. Everything else is a neutral.
- **Nothing is rounded.** Hairlines and square corners. A cut corner marks a control or
  one of the few panels that matter; corner brackets mark the two things that wait on
  the user.
- **Two typefaces with two jobs.** Chakra Petch for what a person reads; JetBrains Mono
  for what the machine said (tool names, arguments, ids, paths, counts, times, logs).
- **Readouts, not paragraphs.** A value gets a small uppercase label. A status is a
  square indicator plus one word. An empty value is `--`.

Contrast: every text tier and every state colour is at least 4.5:1 on every ground in its
theme (the lowest is `--cyan` on `--sunken` in light, 4.6:1). If you change a ground or a
text colour, recheck all five grounds, not just the one you were looking at.

Tints are mixed from tokens in place (`color-mix(in srgb, var(--amber) 12%,
var(--surface))`), never written as new literals, so they follow the theme.

**Rules**

- One primary (filled violet) action per view. The amber fill (`.btn-hot`) is only for
  approving something that was waiting. A refusal or removal is outlined red, never filled.
- Amber means an open question. When a confirmation is answered, its card goes neutral
  (`.prompt-card.resolved`): the colour leaves with the question.
- Cyan is for things that are live right now. "Idle" is not live; it's neutral.
- Selection never rests on colour alone: a selected row has a 2 px rule, a selected
  choice fills its pip, an active segment gets an underline.

## Type

| family | token | fallbacks | licence |
|---|---|---|---|
| Chakra Petch 400/500/600/700 | `--font-ui` | Avenir Next, Helvetica Neue, system-ui | SIL OFL 1.1 (`fonts/ChakraPetch-OFL.txt`) |
| JetBrains Mono 400/500/700 | `--font-mono` | ui-monospace, SF Mono, Menlo | SIL OFL 1.1 (`fonts/JetBrainsMono-OFL.txt`) |

Chakra Petch is Latin only. Both stacks then name macOS faces per script (PingFang SC
and Hiragino Sans for CJK, Apple SD Gothic Neo for Hangul, Geeza Pro for Arabic;
Helvetica Neue covers Cyrillic and Greek) so a non-Latin command falls back to a
chosen face, glyph by glyph, rather than to whatever `system-ui` resolves to.

Both are bundled as woff2 and loaded with `@font-face` from `fonts/`; nothing is fetched.
Chakra Petch is the Latin subset (from Fontsource's build of the Google Fonts release);
JetBrains Mono is the upstream webfont. Ligatures are off (`font-variant-ligatures:
none`): `->` in a command must look like what will run.

## Space and geometry

| token | value | use |
|---|---|---|
| `--s1` … `--s7` | 4, 8, 12, 16, 24, 32, 48 px | all padding and gaps |
| `--hair` | 1 px | every border |
| `--rule` | 2 px | state rules: selected row, user message, callout, error field |
| `--cut-sm` | 6 px | cut corner on controls (buttons, choices, chips, the voice pill) |
| `--cut-md` | 10 px | cut corner on prompt cards, the composer, toasts, the overlay card |
| `--cut-lg` | 14 px | cut corner on the overlay plate |
| `--bracket` | 12 px | arm length of a corner bracket (2 px thick) |
| `--led` | 6 px | square status indicators and pips |
| `--control-h` | 30 px | buttons, inputs |
| `--hit` | 28 px | minimum hit target (small buttons, switches, icon buttons, chips) |
| `--sidebar-w` | 216 px (196 below 1060 px wide) | the rail |
| `--topbar-h` | 64 px | the heading bar |
| `--gutter` | 92 px (76 below 1060 px) | the transcript's who/when column |

- Border radius is 0 everywhere. Don't add one.
- **Cut corners.** Controls lose their bottom-right corner; panels that carry one lose
  their top-right. The cut is a `clip-path` on two stacked pseudo-elements (outline
  colour, then the fill inset by one hairline), because a real border is clipped away
  along the diagonal. Set `--cut`, `--cut-line` and `--cut-bg` on the element; the fill
  must be opaque. To give a new component a cut corner, add its selector to the three
  lists at `primitive: the cut corner` in `styles.css`.
- **Corner brackets** (two 12 x 2 px arms in the state colour, on the bottom corners)
  are for the things that wait on the user: the confirmation and proposal cards and the
  overlay's confirmation card. The overlay's reticle has its own on all four corners.
- **Panels** (`.card`) are plain hairline boxes with a header strip. Use one where rows
  belong together (a settings group, a table). Sections inside a detail pane use a
  micro-label with a rule (`.section-label`) instead of another box.
- No drop shadows in the main window. The overlay has the product's one shadow
  (`drop-shadow(0 8px 18px rgba(0,0,0,.4))`), because it floats over other apps.
- The main area carries a 24 px grid of `--grid` hairlines. Panels are opaque and sit on
  it. No noise, no gradients, no glow.

## Motion

| token | value | use |
|---|---|---|
| `--t-fast` | 90 ms | hover, press, level-driven overlay movement |
| `--t-base` | 160 ms | state changes: a switch, a card arriving, a toast |
| `--t-slow` | 320 ms | the overlay arriving and leaving; a floating panel arriving |
| `--ease` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | everything that moves |

Leaving is faster than arriving and accelerates away: `--t-base` with `ease-in` (a toast
leaving, a floating panel leaving).

**Floating panels slide; their windows don't move.** A panel's window is placed at its
real layout bounds and shown (`showInactive`) before anything moves; the frame then
slides inside the window (`panels.css`, "slide"), so it is clipped by the window's edge,
which for a docked panel is the screen's edge. Docked: in from fully past its docked edge
(100% plus the 12 px inset and the shadow's reach), opaque, `--t-slow --ease`. Free: an
`--s5` nudge in from the nearest screen edge with a fade, same timing -- a full slide from
a mid-screen window's own edge would look like it came from nowhere. Out is the reverse at
`--t-base ease-in`, and the window is hidden only once the page reports the slide finished
(`motion-done`; `panels.js` gives up waiting after 600 ms). A show or hide that arrives
mid-slide flips the class and the transition reverses from where the frame is. The window
is never stepped with `setBounds`: macOS clamps a window above the menu bar (a top-docked
panel couldn't start off-screen), a window off one display's edge appears on its
neighbour, and every reader of the bounds (drag, resize, auto-hide, the saved layout)
would see in-between values.

Indicators blink in two steps (`steps(2, jump-none)`, 1 s; 0.5 s while thinking) rather
than fading: connecting, listening, recording, awaiting approval. Under
`prefers-reduced-motion: reduce` every animation and transition collapses to 1 ms (not
`none`: a toast is removed on `animationend`, and a panel's window is hidden on
`transitionend`, both of which still have to fire). Chromium follows macOS's "Reduce motion"
setting for that media query, so a panel then simply appears and disappears.

## Icons

`LX.icon(name)` in `js/util.js`: 24 px viewBox, 1.6 px stroke, square caps, mitred joins,
`currentColor`. Add a path to `PATHS` in the same style. No emoji anywhere in UI strings,
including the ones `main.js` sends to the transcript; a notice there carries
`notice: "success" | "warning"` and the renderer draws the icon.

## Logo

- `img/mark-*.png` are the mark from `assets/1.png` with the white removed: flat violet
  with the shape in the alpha channel. Regenerate with
  `cd app && env -u ELECTRON_RUN_AS_NODE npx electron scripts/make-mark.js`.
- In the UI the mark is always a CSS mask (`.brand-mark`, `.empty-mark`), so its colour
  is a token: `--violet` in the rail, `--mark-empty` in the empty Assistant view.
- The wordmark in the rail is set in type (Chakra Petch 700, tracked), not the script

- `assets/` originals are not used by the renderer. The dock and tray icons are unchanged

## Overlay (and the Qt port)

The overlay window is 460 x 300, transparent; the stage is 420 px wide, 10 px from the top.

**Plate** (`.island`): `--surface` fill, 1 px outline of the state colour mixed 55% into
`--line-strong`, top-right corner cut 14 px. Padding 10 px (right: 20 px). Contents: the
asset slot (56 px square by default, `manifest.size`), a 1 px `--line-strong` divider,
then the label over one line of text (12 px gap either side of the divider).

- Label: micro-label style (mono 10 px / 500 / 0.12em / upper) in the state colour.
- Line: Chakra Petch 13 px, line-height 1.4, `--text`; hints in `--text-2`; two lines max.

**State colour** (`--tone`):

| state | colour |
|---|---|
| `listening`, `hearing` | `--cyan` (the mic is live) |
| `transcribing`, `thinking`, `speaking` | `--violet-hi` (Leutheria is working or talking) |
| `awaiting_confirmation` | `--amber` |

**Reticle** (the placeholder for a state with no asset; `.orb` in the CSS, `Orb.qml` in
Qt). Three flat parts in the state colour, sized as a share of the slot `S`:

- frame: four corner brackets, arms `0.16 S` long, 1 px thick, at the slot's corners
- core: a solid square `0.26 S`, rotated 45 degrees, centred
- ring: a 1 px square outline `0.50 S`, rotated 45 degrees, centred, 45% opacity at rest

`L` is the smoothed mic level, 0 to 1.

| state | core | ring |
|---|---|---|
| `listening` | opacity 1 to 0.45 and back, 2.8 s ease-in-out | opacity `0.3 + 0.7 L`, scale `0.92 + 0.3 L` |
| `hearing` | scale `0.8 + 0.9 L` | 2 px thick, opacity `0.4 + 0.6 L`, scale `0.9 + 0.5 L` |
| `transcribing` | scale 0.7 | opacity 1, one turn per 1.1 s, linear |
| `thinking` | one turn per 2.6 s, linear | opacity 1 to 0.45 and back, 1.3 s |
| `speaking` | still | scale 0.55 to 1.35 while opacity 1 to 0, every 1.5 s, `--ease` |
| `awaiting_confirmation` | blinks: opacity 1 / 0.25 in two steps, 1 s | opacity 1 |

Level-driven properties follow with a 90 ms linear transition.

**Confirmation card** (`.ov-confirm`), 8 px under the plate: `--surface` fill, outline
`--amber` mixed 60% into `--line`, top-right cut 10 px, amber brackets on the bottom
corners. Header 30 px: warning icon 13 px and "APPROVAL REQUIRED" as an amber
micro-label, with a 1 px rule under it (amber 35% into `--line`). Body padding 10/14/14:
the command in a code well (mono 12 px, `--sunken` fill, 1 px `--line`, two lines max),
then a row with the hint (Chakra Petch 12 px, `--text-2`) and two small buttons, Decline
(outlined red) then Approve (amber fill, `--on-accent` text). Once answered the buttons
are replaced by a check or cross (green or red, 12 px) and the outcome in mono 11 px
`--text-2`, and the card hides after 1.1 s.

**Arriving and leaving**: opacity 0 to 1 and 8 px down from above, 320 ms `--ease`; the
reverse on leaving. The card drops in 6 px over 160 ms.

The state rules themselves (which state shows when, the text of each line, how a
confirmation settles) are in `overlay/overlay.js` and did not change with the redesign.

## Patterns

**Grouped list (the Library).** A list pane of three parts: a state-filter strip that is
also a readout (count over a micro-label; pressed = `--raised-2` fill and the violet
underline of an active segment; a filter with nothing to show is dimmed and inert), then
groups. A group heading is a sticky `--sunken` strip (caret, micro-label name, count) and
a button that folds the group; folded groups are remembered per viewer. Rows are one line,
`--hit` tall: kind icon, mono name, tags only for what's out of the ordinary (`learned`
violet, `ask` amber, `off` dashed). A search that matches inside the description adds a
second line with the excerpt; hits are `<mark>` (violet 38% behind `--text`). While a
search or state filter is on, every group with results is held open. Group membership is
display-only and lives in `js/library-groups.js`, with Other as the fallback.

**Model-facing prose for a human.** Tool and skill descriptions are written for the model
and are not ours to rewrite. The detail pane splits one on sentence ends: the first
sentence is the summary (`--fs-lg`, `--text`, 60ch); the rest goes under "When Leutheria
uses it", one sentence per line in `--text-2`, threaded on a hairline (66ch). Another
capability's name in the text becomes a mono violet link that selects it.

**Empty state.** The mark is an emblem, not a watermark: 184 px, framed by four corner
brackets in `--line-strong` (the reticle's frame), with the readout (eyebrow, title,
sentence, key list) set beside it, left-aligned. Nothing sits behind text.

**Log readout.** One `div` per line inside the `pre`, so it stays one selectable block.
The source tag is tinted by who wrote it (`[bridge]` `--violet-hi`, `[agent]` `--text`,
`[overlay…]` `--text-2`); only an error stream (`:err`) takes a state colour: red tag, a
2 px red rule, a 6% red wash. Continuation lines hang 2ch in. New lines are appended,
never a full rebuild.

**Toasts** sit bottom-left of the main column (raised above the composer on the
Assistant view), because row actions (Revoke, Reset, Delete) are on the right. A long
name wraps inside the toast.

**Confirmation extras.** An agent `reason` is a line under the command, keyed WHY in a
micro-label. `voice_approvable: false` is a state, so it is amber: NEEDS A CLICK as a
micro-label with an amber indicator (on the main card, a 2 px amber rule and 8% wash; on
the overlay, in place of the spoken-answer hint). A timed-out confirmation settles with a
cross and "Timed out with no answer. It wasn't run." Once answered, both cards go
neutral (`.resolved`: `--tone: --text-3`).

**Settings error notice.** `inventory.settings_errors` renders a full-width danger callout
under the heading bar on Library and Permissions only, since those are the settings it
affects.

**Shared skills (a stranger's procedure).** `js/library-shared.js`, styles under
"Library: shared skills" in `styles.css`. The colours carry more weight here than anywhere
else, so they follow the state rule strictly:

- Amber: what will ask you. A `run_command` step (2 px amber rule and a 7% wash on the
  step, the tool name amber, an "asks every run" tag), the `>_` mark on a row with such a
  step, a screener flag, `update`, medium risk, and the cap ("At the limit", the
  needs-click pattern).
- Red: refused or withdrawn. High risk, `withdrawn`, and an index that failed its
  signature check or has no key. A refused index is a *security* state, not an error: the
  danger callout with an 11% red wash and a red outline (heavier than an ordinary error),
  a struck shield icon, `role="alert"`, the agent's own words in mono, and a red indicator
  plus "refused" in the overview readout. An unreachable registry is a neutral callout
  (`.callout-neutral`, `--text-3` rule): nothing is wrong with what's installed.
- Green: only "verified" on the index signature readout. Low risk is a neutral tag, never
  green: passing a screening is not the same as being safe.
- The install card is a prompt card (amber, cut corner, brackets) because it waits on the
  user; it goes neutral (`.resolved`) once installed. Arguments are shown one per line,
  key in `--text-3`, value in full (`.step-args-full`), never truncated. The one action
  is the amber Install (`.btn-hot`: approving something that was waiting).
- Share preview: a `.card` with File / Changed / Check rows (64 px micro-label column),
  removed values struck through in `--text-3`, new ones in `--text`, values to check as
  needs-click rows, then the JSON in a code well capped at 280 px. Open on GitHub is the
  view's one violet primary.
- Rows carry the author and version as a second mono `--fs-xs` line; tags only for what's
  out of the ordinary (high risk, update, withdrawn, `>_`). The main window's Shared
  state strip is two by two (its words are longer than the 80 px cells).

## User customization

What the user can change (the Overlay view), and why only that:

- **Theme**: dark, light or system. Unchanged rule: the light theme overrides tokens only.
- **Density**: `[data-density="compact"]` overrides the larger space steps (`--s3`..`--s7`),
  `--control-h` (26), `--hit` (24, still WCAG 2.2's minimum), `--topbar-h` and `--fs-lg`.
  Tokens only, like the light theme.
- **Accent**: replaces the brand family (`--violet`, `--violet-hi`, `--violet-lo`,
  `--grid`, `--mark-empty`) from one colour, per theme, in `app/overlay-settings.js`:
  `--violet-hi` is lifted (dark) or deepened (light) until it is 4.5:1 on all five grounds,
  `--violet` until 3:1 (marks and rules), `--violet-lo` darkened until white text on it is
  4.5:1. The Violet preset means "no override": the hand-tuned tokens above stay.
- **Not editable: the state colours.** Cyan, amber, red and green mean live, waiting,
  failed and succeeded; a user who could recolour them could make a destructive approval
  look like a success. An accent within the hue window of one of them (16 degrees, 24 for
  amber, at saturation 0.35 or more) is refused with a sentence naming the state.
- **Opacity** is a window property (`setOpacity`), 60-100%, so text contrast is measured
  against what's behind the panel as well; 60% is the floor for that reason.

## Patterns: floating panels

A panel is the overlay's kind of object, so it gets the overlay's treatment rather than
the main window's: the frame is `--surface` with the top-right corner cut `--cut-lg` and
the one drop shadow, 12 px inside a transparent window (room for the shadow and the resize
edges).

- **Heading** (44 px): a grip (six dots, `--text-3`), the panel name as a panel heading,
  the view's subtitle in mono `--fs-xs` `--text-3`, then the **control strip**: icon
  buttons (`--hit` square) for dock, orientation, opacity, pin, close. Pinned is a state,
  so it's the pressed fill plus the active segment's 2 px violet underline, not colour
  alone. Dock and opacity open a popover (`--raised`, `--line-strong` hairline; a menu of
  `--hit` rows with a pip for the chosen dock).
- **Body** is the main window's own view, narrower: the transcript gutter drops to 68 px,
  cards stack their description under the heading, the Library list sits over a short
  detail (name, first sentence, the two switches, "Open in the Library").
- **Horizontal** is a strip, never a squashed column: transcript turns become columns
  separated by a vertical hairline (the turn rule rotated), timers become a row of cards,
  the Library's groups become columns, a card per column on Activity and Permissions.
- **Timer card**: `--raised`, hairline, a 2 px violet left rule (a running thing, not a
  state colour: it isn't live input, waiting or failed), name, `#id` in mono, remaining as
  a `--fs-3xl` mono readout with tabular numbers, ENDS/LENGTH micro-labels, an outlined red
  Cancel.
- **Voice panel**: the session state as a readout (an indicator square plus the word,
  `--fs-2xl` mono, in the overlay's state colour), then LAST HEARD / LAST REPLY with `--`
  for none.
- **Alerts anchor picker**: a 128 x 80 hairline "screen" with seven spots; the chosen one
  is filled `--violet-hi` with a ring, and named beside the picture.

## Focus and accessibility

- Every interactive element shows `:focus-visible` as a 2 px `--focus` outline. Inside a
  list or the rail it is inset (`outline-offset: -2px`) so neighbours don't clip it; on a
  cut-corner control the ring sits on the unclipped element, outside the cut.
- The composer is focused almost always, so it rests with a `--text-3` outline; the full
  `--focus` ring appears when focus arrives by keyboard (`body[data-modality="keyboard"]`,
  set by app.js on Tab/arrow/slash, cleared on pointer down). Fields match
  `:focus-visible` however they were focused, which is why this is tracked by hand.
- Custom controls carry their roles: `.switch` is `role="switch"` with `aria-checked`,
  labelled and described by its setting text; segmented and state filters are
  `aria-pressed` buttons in a labelled group; group headings carry `aria-expanded` and
  `aria-controls`; the selected row is `aria-current`; the list is one tab stop with a
  roving tabindex. The transcript is `role="log"` (polite), toasts a `status` region.
- Panels never take focus by appearing (`showInactive`, no autofocus); the panel's
  controls carry labels and `aria-pressed`/`aria-expanded`, and the dock menu is a
  `menuitemradio` group.
- Contrast: the colours added in this pass are mixes of existing tokens over existing
  grounds (`<mark>`, the needs-click wash, the log error wash) and keep text at
  `--text`/`--text-2`, which clear 4.5:1 on every ground; the state colours used as text
  are the existing ones.
